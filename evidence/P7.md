## V7.2 — install from the tarball

```
npm pack --pack-destination /tmp/opencode            → pi-chrome-search-0.1.0.tgz
cd /tmp/opencode/pi-project && npm install <tarball> --legacy-peer-deps → 2 packages (the extension + ws)
  (without the flag npm also auto-installs the peer chain: "added 125 packages")
pi install /tmp/opencode/pi-project/node_modules/pi-chrome-search
pi -e …/node_modules/pi-chrome-search/src/index.ts --print "reply with exactly OK" → OK
```

The installed package loads in pi and answers. Two findings, both recorded rather than papered over:

- `pi install ./tarball.tgz` records the archive path and the loader then rejects `.tgz`; installing the
  **directory** (npm-installed package or an extracted tarball) works. Users should `npm install` the package
  (or a git checkout) rather than hand pi a tarball.
- Running the packaged CLI with plain `node` fails with `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` —
  Node 26 refuses to strip TypeScript under `node_modules`. pi's own loader handles it (that is how the
  extension loads); the `doctor` CLI stays a repo command (`node src/cli/doctor.ts`), and installed users use
  `/web-doctor` inside pi. No `bin` entry was added for that reason.
