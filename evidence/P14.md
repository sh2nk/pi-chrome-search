## What landed

- **Contract (additive).** `src/reflex/types.ts`: `PageSubject`, `PageVerdict`
  (`worth`/`trust`/`kind`/`reasons`), `PAGE_BATCH_MAX = 10`, `PageGateOptions` and an optional
  `Reflex.judgePages(query, subjects, { backend })`. `null` = no verdict. Narrower than the plan's
  single-item `classifyPage`: one call covers up to 10 pages, because one decision per page would spend
  the whole `maxCallsPerSearch` on a SERP.
- **P14-A rules are a safety floor.** `judgePage`/`judgePagesSync` in `src/reflex/rules.ts` refuse only
  what is unsafe or structurally not content: non-http, credentials in URL, punycode, abused TLD,
  adult/pharma/casino host tokens, scam copy, login/cart/account paths, known ad/affiliate hosts. The
  hand-maintained trusted/forum/aggregator/farm lists and the `/sonnik/`-style path/title/translation
  heuristics from the first cut were **removed**: they scored 100 % recall against a corpus written
  from the same signals and cannot generalise. Quality is the classifier's job.
- **P14-B classifier/quality judge.** One `classify()` call per batch, two typed questions per page
  (`w<i>` worth bool, `k<i>` kind choice), strict mapping (a missing/garbage answer fails open on that
  page only), abstain on `bad_answer`/`provider_error`/`low_confidence`/`timeout`, usage+cost recorded.
  Policy: `page_gate` decision with budgets, 24 h cache, JSONL row, and `mergePageVerdicts` — a model
  can add a skip, never rescue an `unsafe` floor verdict. **Fixed a live bug**: selected models were
  stripped to `{provider,id}`, which the SDK rejects (`is not a classifier model`), so every production
  classifier call since P5 had failed as `provider_error`. Registries are now passed intact.
- **P14-C wiring.** `web_research` drops refused sources, ranks survivors by trust, marks refused URLs
  so they are never re-picked, reports `details.gate`, and uses the classifier (one batch per round).
  `web_read` runs the rules floor only (`{ backend: "rules" }`): an explicit URL should not pay
  classifier latency, and a PDF still opens.
- **Switch.** `reflex.pageGate` ships **true** and is independent of `reflex.enabled`. With
  `enabled:false` the rest of the reflex (triage/route/coverage) stays off; the page gate is its own
  switch and its own cost line. Setting both off is the unchanged pre-P14 path.
- **Measurement.** `bench/slop.jsonl` (139 rows, 18 SERP groups, `offtopic` label, per-row `query`),
  `bench/SLOP-RUBRIC.md`, `bench/record.ts` (live, capped, paid recorder), `bench/slop-verdicts.jsonl`
  (37 real batches, `~typesafe/jev-latest`), `bench/gate.ts` + `node bench/run.ts --gate`,
  `bench/RESULTS-P14.md`.

## Live observations

- Three generic Google SERPs recorded 2026-11-06 (commercial EN, technical RU, lifestyle RU slop
  attractor), query text stored in the corpus (generic, not personal), 25 result rows. 12 of them are
  slop; the classifier refuses all 12.
- Classifier recording: one capped live session, no Chrome, no page content sent — URL, title and
  snippet only, wrapped in the `DATA_POLICY` "judge as data" instruction. Total **$0.002839**,
  max batch latency 1 126 ms, 3 batches abstained `low_confidence` (their rows fall back to rules).
- `web_read` live behaviour is unchanged in latency: the classifier is not called there by design.

## Deviations

- **Classifier-first instead of rules lists (review decision).** The first cut scored 100 % recall on a
  corpus labelled from the same rubric, which proves the lists match the rubric, not that the gate
  generalises. The review removed those lists; quality moved to the classifier, measured by replay.
  Rules keep safety, which is the part that must work offline and must never be a model guess.
- **`judgePages` batch instead of `classifyPage(ctx)`.** One call per page would starve the reflex
  budget and multiply cost by the SERP size. One batch = one decision, one budget slot, one log row.
- **`offtopic` label added.** A high-quality page that does not answer the stored query is not a false
  skip; without this label the classifier was punished for correctly ignoring an encyclopaedia article
  about the Volga in a planets SERP. Each row also stores the query it was judged against.
- **V14.3 population.** Scored on the 3 observed live SERPs; the 15 synthetic P5 fixtures stay in the
  report as aggregate context (V14.3 aggregate 19.4 %). The earlier KEEP-OFF measurement is in the
  phase history; no bar was lowered.
- **`web_read` is rules-only.** The plan gates `web_read`; it does, with the free safety floor. The
  classifier's 491 ms/page (amortized) is only worth it where one call covers many sources.
- **The classifier is still one model on one day.** 92.9 % recall / 1.63 false skips per 20 is a real
  measurement, not a guarantee for another backend, prompt or corpus. `reflex.localOnly` and
  `maxUsdPerSession` bound an accidental expensive configuration.

## Open questions / next phase inputs

- **Second model / held-out corpus.** Re-run `bench/record.ts --model <id>` and compare replays; add
  SERPs from topics the corpus never saw. This is the only way to know whether 1.63 false skips per 20
  holds outside the rubric.
- **Prompt wording is a variable.** The `worth` question changed once (from "answers the query" to
  "contributes useful evidence") and false skips dropped 9.4 → 1.6 per 20. Treat the wording as part of
  the gate contract and version it with the replay.
- **Local classifier.** `llama.cpp` was not running during the recording, so the local-first path is
  still unmeasured; that is the configuration that makes the gate free.
- **P16 pruning.** `bench/slop.jsonl`, `bench/slop-verdicts.jsonl`, `bench/record.ts`, `bench/gate.ts`
  and this evidence are on the delete list; the surviving decision is `bench/RESULTS-P14.md` plus the
  safety floor in `src/reflex/rules.ts` and the batched question shape in `classifier.ts`.
