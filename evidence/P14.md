## What landed

- **Contract (additive).** `src/reflex/types.ts`: `PageSubject`, `PageVerdict`
  (`worth`/`trust`/`kind`/`reasons`), `PAGE_BATCH_MAX = 10`, and an optional
  `Reflex.judgePages(query, subjects)`. `null` = no verdict, callers keep their old behaviour.
  The plan sketched a single-item `classifyPage(ctx)`; the shipped shape is a batch, because one
  decision per page would spend `maxCallsPerSearch` on a SERP — one call covers up to 10 pages.
- **P14-A rules** (`src/reflex/rules.ts`): `judgePage`/`judgePagesSync` — unsafe (punycode, abused TLD,
  credentials in URL, adult/pharma/casino host tokens, scam copy), trusted publishers/allow-listed docs,
  forum, aggregator, farm host, off-topic path (`/sonnik/`), slop title markers, translated-text markers,
  thin/boilerplate excerpt (only from a ≥400-char read window, never a snippet), informational sub-page
  on an unrecognised host, unknown (read it).
- **P14-B classifier** (`src/reflex/classifier.ts`): one `classify()` call per batch, two typed questions
  per page (`w<i>` worth bool, `k<i>` kind choice), strict mapping (missing/garbage answer → that page
  fails open as `unknown`/worth), abstains on `bad_answer`/`provider_error`/`low_confidence`/`timeout`,
  usage+cost recorded. **Policy** (`src/reflex/policy.ts`): new `page_gate` decision with the P5
  guarantees (disabled = zero calls, budget, 24 h cache, JSONL row) plus `mergePageVerdicts`: a model may
  add a skip, but never rescue an `unsafe` rules verdict.
- **P14-C wiring**: `web_read` gates before a tab is acquired (one line: kind + reasons) and composes with
  the pre-P14 `gateRead` when the page gate abstains; `web_research` drops refused sources, ranks the rest
  by trust, marks refused URLs so they are never re-picked, and reports `details.gate`.
- **Bench**: `bench/slop.jsonl` (139 labelled rows, 18 SERP groups), `bench/SLOP-RUBRIC.md`,
  `bench/gate.ts` + `node bench/run.ts --gate`, `bench/RESULTS-P14.md`.

## Deviations

- **`judgePages` instead of `classifyPage(ctx)`.** The plan's sketch was one page per call. With
  `maxCallsPerSearch` shared with triage/coverage, a SERP-sized gate would starve the rest of the
  reflex. The batch is one decision, one budget slot, one cache entry, one log row.
- **`/blog/`-style path rule is deliberately blunt.** It catches shop-blog and vendor lead-gen slop on
  unknown hosts (3 live rows) at the cost of a theoretical false skip on a good vendor blog. Measured
  false skips: 0/97. This is the rule the classifier should eventually replace.
- **Corpus recall is partly circular.** The rubric and the rules list encode the same visible signals
  (farm host, off-topic path, abused TLD). The non-circular numbers are: 0 false skips on 84 recorded
  good URLs + 8 aggregators, 12/12 live slop refused, and the conditional read removal (75 %).
- **V14.3 fails honestly.** A quality gate only saves reads where the read window contains junk; clean
  SERPs save nothing, so the unconditional 25 % bar is unreachable on a CORPUS-MIXED set. The plan
  anticipated this outcome ("verdict may be stay off"). No bar was lowered and no clean query was
  dropped from the simulation to raise the average.
- **Classifier accuracy and cost are unmeasured.** `classify()` needs a live `pi` session and the user's
  provider; the offline bench cannot call it. Unit tests cover batching (10 pages = 1 call, 20
  questions), strict mapping, per-page fail-open, abstention reasons, budget, cache and the
  `decisions.jsonl` usage/cost row. Proving the long tail needs a held-out live corpus.
- **Cost row marked UNMEASURED, not PASS.** The rules path is genuinely $0, but V14.4 is about the
  classifier price at the observed batching; marking it measured would repeat the small lies P9 removed.

## Open questions / next phase inputs

- **Held-out live corpus.** Label ~60 URLs from SERPs the rules were not written against (different
  topics, EN and RU), then compare rules vs classifier on the same rows. That is the measurement that
  can justify turning the gate on; this corpus cannot.
- **A `reflex.gate`-only switch.** The gate is now the honest half of the reflex, but it can only run with
  `reflex.enabled: true`, which also enables triage/route/coverage. If the next session wants the gate
  without the rest, split the flag (config change + doctor + bench) rather than raising `enabled` by
  default.
- **P16 pruning.** `bench/slop.jsonl`, `bench/gate.ts`, `bench/results/` and this evidence are all on the
  P16 delete list; the surviving decision is the five lines in `bench/RESULTS-P14.md` plus the rules
  floor in `src/reflex/rules.ts`.
