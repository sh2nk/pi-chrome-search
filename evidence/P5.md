## Rule set (P5-B)

- triage: BM25 over title+snippet, domain prior (docs/wiki/gov/edu up; ad/shortener/clickbait down), exact-URL
  dedup, best-first top-k (default 6), advisory `spam`/`duplicate` flags, never empty for a non-empty SERP.
- gateRead: spam/clickbait/login/cart/binary deny; allowlisted host needs 1 query-term hit, unknown host 2.
- coverage: `enough` = ≥2 distinct domains **and** ≥1 exact-term hit; otherwise `read_more`/`refine` with the
  "no new domains" rule.
- route: Cyrillic → `yandex,google` + `lang:ru`, Latin → `google,duckduckgo` + `lang:en`, freshness from
  news/date keywords, `n:3`/`summary:false` for one-term queries.
- policy: `enabled:false` performs **zero** model calls; abstain on `confidence < 0.55`, `stopReason !==
  "stop"`, `errorMessage`, or `latencyMs > 1200`; per-search 30 / per-session 500 / $0.05 budgets fall back to
  rules without throwing; 24 h verdict cache; every decision JSONL-logged with a hashed query and
  origin-only URL (no snippets, no tokens).

## Bench (P5-A)

`bench/queries.jsonl`: 30 queries (6 per class: factual, technical, commercial, news, ambiguous; 15 EN / 15
RU), 2–4 golden domains each, no personal data. 15 synthetic SERPs (99 results, one `spam-seo.example`
sentinel each) for deterministic offline replay.

```
npm run bench -- --no-write
bench offline: 30 queries (30 ok) in 10 ms
recall@5 0.789 (71/90 goldens in top 5)
tokens 8702 (chars 34768, avg 290.1/query)
latency p50 0.15 ms / p95 0.43 ms
spam leaked 16/30
```

The baseline deliberately leaks the spam sentinel (16/30) so the triage metric can move. Live mode refuses to
start without `PI_CHROME_LIVE=1`, an explicit `--limit` (cap 5; `--allow-more` for a deliberate larger run),
and results land in the gitignored `bench/results/`.

## V5.6 verdict — the reflex stays off

`bench/RESULTS.md` records the three runs and the reasoning. In short:

- ruling triage that still returns the requested `n` (`keep 6`): recall **+7.78 pts**, spam leakage halved
  (16 → 12 of 30), tokens **−0.2%** — fails the ≥20% bar;
- `keep 3`: recall ±0, tokens **−37.2%**, but it returns three results where the user asked for five. The
  metric is satisfied by delivering less, which is not what SPEC §9.4 buys.

So `reflex.enabled` ships **false**, `reflex.triage.keep` stays 6, and the read-gate half of V5.6 is recorded
as unmeasured (no honest offline source; a live file would be needed).

One opt-in live pass was still executed to prove the live path works end to end:
`PI_CHROME_LIVE=1 node bench/run.ts --live --limit 1` → 1/1 query ok, recall@5 0.333 (1 of 3 goldens),
400 tokens, 3.77 s, `bench/results/20261106-044916-live.json` (gitignored). One query, no retry, no wall.
It is not a reflex measurement — it is the harness proving it can run live without a loop.
