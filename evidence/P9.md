# P9 — M9: read integrity and the small lies

Date: 2026-11-06
Owner: orchestrator
Verdict: **PASS** on the offline gates (V9.1–V9.5, V9.6 offline/logic); **V9.6 live PASS on the repaired
build**, with one honest caveat (the Chrome Allow prompt, P11).

Plan: `PLAN-v2.md` §4 (P9-A..P9-E). The field defects: four parallel `web_read` calls returned the last
navigation's body; a failed read left no artifact; `offset` past the end returned `""`; `maxChars: 99999`
was silently narrowed; `web_doctor fix` claimed a failed reconnect for a browser that was alive;
`probe:false` reported every engine `unavailable`; `n=3` across two engines let one engine fill every slot;
Yandex `pageUrl` is an image file but the caller was never told.

## What landed

- **Contract** (`contract: read locks, nav proof, pageUrlKind`): `PageKey` gains `read#<n>` pool slots;
  `CdpPage.currentUrl()` (authoritative `location.href`, refreshes the cached `url()`); `config.read.pool`
  (1..3, default 1); `ImageItem.pageUrlKind: "page" | "image"`; two frozen error codes
  `E_NAVIGATION_MISMATCH` (retryable) and `E_OFFSET_RANGE` (not retryable).
- **P9-A** `src/cdp/page-lock.ts`: keyed FIFO lock (no leak on a throw, per-connector via `WeakMap`,
  `pick()` = least-loaded slot) + `readSlotKeys()`. `web_read` takes the lock per slot and calls
  `acquirePage("read"|"read#n")` *inside* it; `acquirePage` remains idempotent.
- **P9-B** post-navigate proof: `landed = await page.currentUrl()` before the SSRF re-check, then the same
  call after extraction; a changed document is `E_NAVIGATION_MISMATCH`, never a stranger's page. The
  requested-vs-landed comparison is deliberately not an error: a legitimate redirect must not fail a read
  (the redirect is re-guarded and reported as `finalUrl`). This also fixes the stale `page.url()` after a
  typed search recorded in `research/FINDINGS.md` §12.5.
- **P9-C** `saveFailureArtifact()` in `runtime/artifacts.ts` (one call site, three tools). `web_read`
  snapshots `E_PARSE`, `E_TIMEOUT`, `E_BLOCKED_URL` (after redirect) and `E_NAVIGATION_MISMATCH`; a
  transport failure (no page state) deliberately writes nothing.
- **P9-D** truth pass: `E_OFFSET_RANGE` names `totalChars`; `details.maxChars`/`clamped`/`totalChars` make
  the clamp visible; doctor `skipped` verdict (keeps the report `degraded`); a fix re-probes even with
  `probe:false`; a timed-out connect is re-checked on the same promise (`... (after the deadline)`) and a
  post-release reconnect is attempted only when the session is gone (`session still open; reconnect not
  required`); a merged search splits `n` as `ceil(n/k)` and reports
  `google:2 yandex:0(E_WALL)` (header, `details.perEngine`/`failedEngines`, JSON view recomputed after the
  fit).
- **P9-E** `image_search`: `pageUrlKind` in items and details, `pageUrl` semantics in the description
  (Google = host page, Yandex = source image file). Byte-level `attach` stays P12-C.
- **Tests**: `tests/unit/page_lock.test.ts` (new), 13 new `web_read` concurrency/artifact/range tests,
  per-engine accounting in `compact`/`web_search`, `pageUrlKind` in `images`, reconnect honesty in
  `doctor`/`doctor_engines`, and the opt-in live gate `tests/live/read.test.ts`.

## V9.6 — `web_doctor --fix` has no false reconnect claim; the report stays honest (live)

Final run, once, on the repaired build:

```
node src/cli/doctor.ts --json --fix --no-probe
```

```
fix: connected to CDP
fix: closed 1 owned tab(s)
fix: reconnected after release
fix: pruned artifacts: 0 removed, 2 kept
```

```
verdict=degraded cdp=ok
google skipped — probe not requested (probe:false)
duckduckgo skipped — probe not requested (probe:false)
yandex skipped — probe not requested (probe:false)
```

Exit 0, 3.0 s. Every line is true: a connect happened, one owned tab was closed, a reconnect was required
(the session was gone after `releaseAll`) and succeeded, and a skipped probe is reported as `skipped`
(never `ok`), which keeps the verdict `degraded` rather than claiming health without evidence.

**Caveat (honest):** an earlier run of the same command on the same Chrome logged
`connect failed: E_CDP_UNAVAILABLE` + `reconnect failed: E_CDP_UNAVAILABLE` and then reported `cdp: ok`
from the same process. The cause is the Chrome 136+ **Allow** modal, which the user does not always see in
time: the connect sits behind the unanswered prompt, outlives the doctor's 7 s budget (5 s connect + 2 s
discovery), and succeeds afterwards. P9 makes that outcome impossible to mislabel (late grace on the same
promise + `... (after the deadline)`), but it cannot make the prompt visible. That is **P11** (blocking
wait + desktop notification + best-effort raise), recorded in `research/FINDINGS.md` §13.4 and in the
phase's status note.
