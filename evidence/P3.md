## Harness

`tests/helpers/dom.ts` runs an adapter's extraction function twice from one source: live via
`page.evaluate("(" + extractFromDocument + ")(document, …)")`, offline via `node:vm` over a `linkedom`
parse of the fixture. `tests/unit/dom_harness.test.ts` proves the harness itself is real (parses the
largest Google capture, finds organics, fails on a closure). `linkedom` is a devDependency only.

## Deviations

- **`/goto` resolution lives in the tool layer** (`src/extract/goto.ts` + `web_search`), not in the Google
  adapter: adapters stay pure DOM extractors. Unresolvable wrappers are kept; success is cached 24 h.
- **`ToolDeps.fetchImpl`** (optional, `contract:` commit) makes the resolver injectable so offline tests
  cannot reach Google.
- **CDP broker** `research/probes/07-cdp-broker.mjs`: Chrome 136+ has no permanent Allow; the broker holds
  one connection and serialises short-lived clients, so a work session costs one click instead of one per
  capture. Live work stays orchestrator-only and serial.

## Validation and repairs

Each adapter had an independent read-only validator (fresh agent, tree copied to /tmp) before the phase
closed. Findings and the repairs that followed:

| Engine | Verdict | Defects fixed |
|---|---|---|
| google | reject | wall pages never reached `detectWall` (settle waited only for `#rso/#search` → `E_TIMEOUT`); text-only wall markers fired on ordinary SERPs; an organic `<section>` mentioning "AI Overview" fabricated an answer; canaries counted `<script>` text; label-strip and home-page guards untested |
| duckduckgo | approve-with-nits | config `kl: "ru-ru"` became `kl=ru-ru-ru-ru`; ad wrapper that was the container was missed; assist block could ship control labels or a nested ad; badge branch untested; a challenge page burned the settle deadline |
| yandex | approve-with-nits | a prose-only Futuris teaser was emitted as an answer; captcha text markers were unconditional; `-Label` siblings hid answers; Yandex-host sources leaked; ad path fragments were not host-scoped; selector not pinned by tests |

Two cross-cutting fixes landed in the tool layer:
- `fix(search)`: a settle `E_TIMEOUT`/`E_PARSE` now asks `detectWall` once, writes the wall snapshot and
  surfaces the window, so `/sorry`, captcha and consent pages report `E_WALL` instead of an unactionable
  timeout (`E_TIMEOUT` is not fallbackable).
- `fix(fixtures)`: the Yandex bootstrap JSON shipped `displayUserName`/`userName`/`avatarId`/`yandexUid`.
  The sanitizer and the audit now cover identity fields; both fixtures were re-sanitized and a regression
  test asserts the values are gone.

Privacy rewrite: because the identity blobs had been committed, history was rewritten with
`git filter-branch --tree-filter` to replace every historical fixture blob with its sanitized version, then
`git reflog expire --expire=now --all && git gc --prune=now`. Verified by scanning every revision that
touches `tests/fixtures` for the name and the identity keys: no hits. Commit hashes before that rewrite
(`05353ed`…`f5499a9`) no longer exist; messages are preserved.
