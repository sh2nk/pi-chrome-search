## Delivered

- **P13-A** `src/extract/claims.ts` (new): sentence splitting (fence-aware,
  abbreviation-aware), boilerplate/lone-date/navigational filters, a code-fragment
  filter, a deterministic score (query-term coverage + numeric/date/named-entity
  presence + position + length fit) and a global ranking across every read page.
  One claim per source, a second only when clearly distinct, identical text
  merged into one claim with several citations. `looksLikeCode` and
  `isTocPage` are exported and unit-tested.
- **P13-B** `src/extract/urls.ts`: `sourceKey()` (canonical host + path, query
  dropped), `stripTrackingFromText()` (Markdown href **and** link text, sentence
  punctuation preserved), plus `ref` in the tracking set. `web_research` now
  de-duplicates a round by `sourceKey`, cleans titles/snippets/excerpts/claims,
  and drops a table-of-contents read from the bundle.
- **P13-C** `src/tools/web_research.ts` + `src/reflex/policy.ts`: claim coverage
  (`claimsCoverage`, threshold `MIN_CLAIM_COVERAGE = 0.6`) is the `enough` gate,
  and a deterministic floor overrides any backend that says `enough:yes` while
  the claims ignore the query (policy `settle` hook, applied before caching and
  logging). `read_more` is honoured before spending a search; the budget is spent
  on refinement instead of declaring victory after one SERP; the header still
  reports the budget actually used.
- Tests: `tests/unit/claims.test.ts` (new, 19 cases), four new cases and one
  adapted case in `tests/unit/web_research.test.ts`, `tests/live/research.test.ts`
  (opt-in).
- Fixtures: `tests/fixtures/claims-qa.json` (ten queries, synthetic `.test`
  pages), `tests/fixtures/research-live-p13.json` (trimmed live transcript).

## Deviations from the plan

1. **`sourceKey` is canonical host+path, not the registrable domain.** Folding
   `docs.python.org/x` and `blog.python.org/x` into `python.org/x` would merge
   two genuinely independent sources and destroy the corroboration signal the
   bundle relies on. The query string is dropped, `www.` is dropped, the host is
   preserved; the doc comment states the trade-off. This keeps V13.2 honest for
   both tracking tails and `?page=` duplicates without trading away independence.
2. **The coverage floor is enforced twice on purpose.** `web_research` applies it
   to the verdict it gets, and `policy.coverage()` applies it to every backend
   answer through a `settle` hook before caching/logging, so a cached verdict can
   never replay an over-eager `enough`. This is why `reflex/policy.ts` is in the
   P13-C file list.
3. **The live gate uses `budget:quick` and RU queries.** The first attempt used
   English queries; this RU profile gets Russian SERPs for them (0/3 coverage),
   and the run also surfaced the code-quote bug. After the code/fence filters the
   gate was re-run once with language-matched queries. Not retried in a loop.
4. **`read_more` now consumes unread candidates before a search.** The shipped
   loop refined first whenever a rewrite existed, so a verdict asking for more
   reading quietly spent a search. The budget ceilings are unchanged.
5. **A table-of-contents read is dropped, not failed.** It still costs its read
   slot (the browser trip happened), it just contributes no excerpt and no claim.

## Open questions / next phase inputs

- Coverage counts tokens, not meaning: an English query against a Russian page
  scores low even when the claim is the answer. P14's classifier is the natural
  place to judge semantic relevance; the deterministic floor stays as the floor.
- The `claims-qa` fixture is a seed for the P14 labelled corpus (good/slop/unsafe
  URLs), not a substitute for it.
