# P12 — M12: binary payloads (PDF reading + image bytes)

**Verdict: PASS** — V12.1–V12.7 recorded below; typecheck, 946 tests and the
13-rule audit are green.

Date: 2026-11-06 · Chrome `157.0.8103.38` (attached, headed) · Node `26.13.0`.
Spike and rejected alternatives: `evidence/P12-spike.md`.

## Delivered

- **P12-A** `src/cdp/bytes.ts` + `CdpConnector.fetchBytes`: a response body is
  fetched by Chrome itself (cookies, redirects, compression are the browser's)
  with `Fetch` at the response stage on a short-lived **background** target. The
  final URL is returned for a second SSRF pass; `Content-Length` is enforced
  before the body when the server declares it. `web_read` branches on
  `document.contentType === "application/pdf"`, reads the bytes, and releases the
  read tab (a PDF viewer tab can leave a detached flattened session behind).
  `read.pdfMaxBytes` (20 MB), `read.pdfPageMaxChars` (4000), `read.keepPdf`
  (off) are new config keys; `keepPdf` writes `doc.pdf` into the artifact dir.
- **P12-B** `src/extract/pdf.ts`, primary rung **in-tree** (the plan's AX-tree
  rung was measured useless on Chrome 157 — see the spike), fallbacks
  `pdftotext -layout` → `mutool draw -F txt` behind `capability()`. Page markers
  `--- p.N ---`, per-page cap, `E_PDF_SCANNED` / `E_PDF_UNSUPPORTED`.
- **P12-C** `image_search attach:"bytes"` (alias `attach:true`): up to four
  thumbnails fetched through Chrome, SSRF-checked, emitted as real image blocks
  (`{type:"image", data, mimeType}`). No re-encode: the base64 is the response
  body. Defaults stay `attach:false`.

## Deviations from the plan

1. **Rung 1 is a parser, not the AX tree.** The AX tree exposes only the viewer
   toolbar on Chrome 157 (spike). The in-tree byte parser is the primary path;
   `pdftotext`/`mutool` remain the optional rungs. PO1 still holds: the gate
   above runs with no capability resolver.
2. **The live gate uses a throwaway agent dir/lock.** The interactive pi session
   that hosts this work holds `~/.pi/agent/web-search.lock` for its own lifetime;
   the live test runs in a child process and would otherwise be `E_BUSY`. The
   test creates its own lock/state under `/tmp/p12-live-*` and closes every tab
   it opened (`releaseAll`). The scanned artifact above was still written by the
   production artifacts root because `createArtifacts` resolves `agentDir()` from
   the process environment; no user data is in it (viewer HTML + meta only).
3. **`E_UNSUPPORTED` is the size-ceiling code.** The taxonomy has no
   `E_TOO_LARGE`; adding one for a single config check was not worth a contract
   change, and the message names the exact size and key.
4. **PDF tabs are released after a read.** Chrome's viewer swap left a detached
   flattened session, which made the *next* read fail `E_TARGET_LOST`; the
   first live run reproduced it. `CdpConnector.releasePage` (optional) closes the
   owned read tab after a PDF, so the next read starts clean. The second live
   run is the one recorded above.
5. **A table-heavy sample URL was replaced.** `assets.accessible-digital-documents.com`
   delivered 16 KB and then stalled for >30 s from this network (curl and Chrome
   alike); the gate uses `pdfobject.com/pdf/sample.pdf` instead.
